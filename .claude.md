# R Analytics Project - Meghbela Cable & Broadband

## Project Overview

This is an R-based analytics and reporting system for **Meghbela Cable and Broadband Services Private Limited (MICBSPL)**, a cable television and broadband operator in India. The project handles monthly subscriber reporting, revenue reconciliation, broadcaster settlements, and operational analytics across multiple LCOs (Local Cable Operators) and distribution entities.

**Primary Functions:**
- Monthly Subscriber Reports (MSR) generation for broadcaster settlements
- Wallet/revenue analysis and reconciliation
- CAS (Conditional Access System) data reconciliation across multiple systems
- IPTV state-level reporting (West Bengal, Bihar, Uttar Pradesh)
- Subscriber trend analysis and forecasting
- LCO performance tracking and payment calculations
- Executive reporting and visualizations

**Geographic Coverage:** Odisha, West Bengal, Uttar Pradesh, Bihar
**CAS Systems:** Gospell, SafeView, ABV, Nagra
**Broadcasters Tracked:** Jiostar, Sony, Zee, Star India, Discovery, and others

## Key R Scripts

### Core Scripts (Source/)

#### `testbench.R` (42.4 KB)
Comprehensive testing and exploratory analysis workspace for data validation and experimental code.

### Monthly Analysis Scripts (Source/Monthly/)

#### **MSR Report Generation**
- `ListActivetoMSR.R` (27.2 KB): Converts MQ active customer lists to MSR format. Tracks subscriptions on 7th, 14th, 21st, 28th of each month. Calculates monthly averages per broadcaster/channel.
- `IPTVMSR.R`, `IPTVMSR_v2.R`: IPTV-specific MSR reports by state (WB, UP, Bihar). Separates HD/SD subscriptions.
- `AreawiseMSR.R`: Area-wise MSR breakdowns
- `PMR_REPORT_MAKE_NEW.R`: PMR (Package Management Report) generation

#### **Wallet & Revenue Analysis**
- `Wallet_analysis.R` (6.4 KB): Processes wallet transactions, calculates LCO-wise revenue, splits direct vs. LCO customers. Exports credit/debit notes and billing reports.
- `Wallet_reconcile.R`: Reconciles wallet data with active services
- `Wallet_Revenue_Paid_Free_Analysis.R`: Revenue breakdown by payment type
- `LCOwise_Monthly_Wallet_analysis.R`: LCO-level financial analysis
- `Broadcaster_wallet.R`: Broadcaster revenue share calculations (88.9% LCO, 80% direct)

#### **Broadcaster Reports**
- `BC_Report.R` (24.5 KB): Package-wise subscriber counts per broadcaster. Generates alacarte and bouquet reports.
- `BC_report_areawise.R`: Area-wise broadcaster breakdowns
- `BC_Report_ZEE.R`: Zee-specific reports
- Covers: Jiostar, Sony, Zee, Discovery, Star India

#### **Reconciliation**
- `Reconcilliation.R`: Matches CAS system data (Gospell, SafeView, ABV, Nagra) with MQ active lists. Identifies discrepancies and missing subscriptions.
- `Wallet_reconcile.R`: Financial reconciliation
- Exports: Missing services, data inconsistencies

#### **Active Customer Analysis**
- `active_analysis.R` (26.1 KB): Counts active subscribers by entity, city, plan type. Identifies services in configuration but not in active lists.
- `ActiveCustomer.R`: Active customer statistics
- Compares MQ lists with SMS (alacarte) lists

#### **Other Monthly Reports**
- `Package_trend_analysis.R`: Package adoption trends
- `Penetration_Percentage.R`: Market penetration analysis
- `Disconnected_analysis.R`: Churn analysis
- Various plan-specific and area-specific analysis scripts

### Tool Scripts (Source/Tools/)

#### **Analysis & Validation**
- `Subscriber_Trend_analysis.R`: Visualizes subscriber trends over time. Generates PNG plots for migration patterns, contract changes, package trends.
- `Audit_MSR_calc.R`: Validates MSR counts across all CAS systems

#### **Operational Tools**

- `DPOpacktoBroadcaster.R`: Maps DPO packages to broadcasters
- `Star_Value_calc.R`: Star India value assignments
- `MSR_details.R`: Extracts MSR-level detail records

## Key Workflows

### 1. Monthly MSR Generation
```
Input: MQ Active Customer List + Package Config Files
  ↓
ListActivetoMSR.R / IPTVMSR.R
  ├─ Load active list (STB, VC, Service Code)
  ├─ Filter on plan types (exclude promotional/deleted)
  ├─ Count subscribers on 7th, 14th, 21st, 28th
  ├─ Calculate monthly averages
  └─ Group by Broadcaster → Plan → Bouquet/Channel
  ↓
Output: MSR_Report_all_*.xlsx (multiple sheets)
        Area-wise and Plan-wise breakdowns
```

### 2. Wallet Revenue Analysis
```
Input: Wallet Transactions + LCO Master + Plan Names
  ↓
Wallet_analysis.R
  ├─ Filter invoices vs. credit notes
  ├─ Calculate LCO-wise debit totals
  ├─ Export by area, plan type, LCO
  └─ Process credit/debit notes
  ↓
Output: LCOWISE_WALLET_SUMMARY_*.csv
        LCO payment reports (ZIP archives)
        RTU customer billing
```

### 3. CAS Reconciliation
```
Input: CAS Files (all systems) + MQ Active List
  ↓
Reconcilliation.R
  ├─ Match MQ with CAS records
  ├─ Identify CAS entries missing in MQ
  ├─ Identify MQ entries missing in CAS
  └─ Separate by CAS system and LCO
  ↓
Output: System-wise reconciliation reports
        Missing service lists
```

### 4. Subscriber Trend Analysis
```
Input: Historical Active Customer Data
  ↓
Subscriber_Trend_analysis.R / Forecasting.R
  ├─ Load time series (monthly customer counts)
  ├─ Clean/normalize service names
  ├─ Generate visualizations
  └─ Apply forecasting models
  ↓
Output: Trend PNGs (plots/)
        Forecast data with confidence intervals
        Executive reports (HTML/PDF)
```

## Usage Notes

### Running Monthly Reports
1. Ensure MQ active list is exported (latest month)
2. Update package configuration files if needed
3. Run `Source/Monthly/ListActivetoMSR.R` for cable MSR
4. Run `Source/Monthly/IPTVMSR_v2.R` for IPTV reports
5. Run `Source/Monthly/Wallet_analysis.R` for revenue analysis
6. Outputs saved to `Output/{MonthYY}/`

### Reconciliation Process
1. Export data from all CAS systems
2. Place files in root or specify paths
3. Run `Source/Monthly/Reconcilliation.R`
4. Review mismatch reports for data quality issues

### Trend Analysis
1. Ensure historical monthly data is available
2. Run `Source/Tools/Subscriber_Trend_analysis.R`
3. Check `plots/` for visualizations
4. Review HTML/PDF reports for insights

### File Naming Convention
- Monthly snapshots: `{Entity}_{MonthYY}.csv` (e.g., `LCO_DPO_count_August25.csv`)
- Reports: `{ReportType}_all_{YYYYMMDD}.xlsx`
- Area-specific: `{Area}_{ReportType}_{Date}.csv`
